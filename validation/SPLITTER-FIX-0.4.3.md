# 0.4.3 分栏私有光标修复验证

日期：2026-09-20。Windows 11 专业版 x64，10.0.26200；AMD Ryzen 5 9600X，12 个逻辑处理器；测试窗口 DPI 168（175%）。Rust/Cargo 1.93.1，MSVC 14.44.35207、Windows SDK 10.0.26100.0；Release、ThinLTO、静态 CRT、PerMonitorV2。比较本机 0.4.2 与 0.4.3，源码基线提交为 `585102d591afed0aafb7f9b84d9c62b1dadd4498`。

**问题与处理**

用户报告在 Codex 左右区域之间的分栏附近甩动难以触发。0.4.2 的两处逻辑会造成同类问题：手势达标时若当前光标不属于登记的标准系统角色，直接丢弃触发；效果期间经过未知角色，则取消动画并重置手势轨迹。前者还会消耗已确认手势的冷却时间，后者使往返越过分栏的轨迹被打断。

[Chromium 的 Windows 光标实现](https://chromium.googlesource.com/chromium/src/+/main/ui/base/win/win_cursor_factory.cc) 将 `kColumnResize`、`kRowResize` 映射到应用资源，而 `kEastWestResize` 使用系统 `IDC_SIZEWE`。因此外观相似的分栏与窗口边缘可能有不同的句柄归属。此源码核实支持故障机制，但本轮没有直接读取 Codex 分栏的实际句柄，也没有对其具体控件做自动化验收。

0.4.3 允许在可见私有光标上启动或延长动画，经过私有光标不再丢弃手势或取消效果。动画依旧只安装 13 种标准系统角色，私有句柄的图像、热点及所有权保持不变；回到标准角色时直接显示当前已安装帧。动画照常到期，返回后不重放过期效果。停留阶段不再因未知角色逐采样执行额外动画检查。

没有新增覆盖层、事件钩子、常驻线程或高频计时器。原来的 15 ms 增长/缩小、最长 100 ms 停留检查、最多 16 帧/2 MiB 缓存、闲置 3 秒释放继续适用。一直停留在私有光标区域时，该图标本身不会放大。

[PowerToys Find My Mouse 当前实现](https://github.com/microsoft/PowerToys/blob/main/src/modules/MouseUtils/FindMyMouse/FindMyMouse.cpp) 使用独立的 Composition/XAML 聚光灯，按位置更新视觉，不依赖替换当前光标角色。因此光标形状切换不会遇到本项目同样的角色限制。本次只修复 ShakeSpot 的状态处理，没有引入 PowerToys 的渲染依赖，也没有进行两项目资源消耗对比。以上外部源码读取日期为 2026-09-20。

**行为与恢复**

- 修改前保存独立 EXE，并用最终驱动的 `--splitter-only` 模式复现失败：私有分栏光标上甩动没有保留效果。
- 新版 54 项 Rust 测试、格式检查及 Clippy 警告视为错误的检查通过；完整桌面回归 124 项通过。
- 私有分栏上启动、离开分栏无需新输入、反复跨越分栏、私有光标像素与热点保持、点击/拖拽阻断、隐藏光标取消、到期恢复与防重放全部通过。
- 1.8 秒跨分栏往返中触发 4 次，首次生效后没有观测到效果中断。离开私有光标后读取到放大帧用时 0.442 ms；标准手形切换为 0.449 ms。这是驱动切换到像素/热点查询成功的耗时，包含查询成本，不是显示呈现或物理鼠标端到端延迟。
- 正常退出、主进程崩溃、主进程挂起、恢复进程失效以及整个进程树结束后的下次启动，均通过系统角色恢复检查。
- 16 轮交替标准/私有光标触发、暂停与缓存清理后，主进程 GDI 15 → 15、USER 16 → 16、内核句柄 186 → 186；恢复进程 GDI 0 → 0、USER 1 → 1、内核句柄 100 → 100。缓存帧数和核算字节数归零。
- 8,192 条突发输入产生 128 次采样，约 2.918 秒完成，程序保持启用。排除应用内持续移动 10 秒时，输入、采样、动画检查及光标更新均为 0；离开排除应用后新手势正常触发。

驱动在自建窗口中使用标准调整大小光标的独立副本，模拟应用私有光标的归属；该副本不是 Chromium 的同一图像资源。完整回归使用独立配置，恢复指针、前台窗口和鼠标位置。顺便修复了测试驱动中一次私有测试光标未释放的问题，不涉及产品光标所有权。
