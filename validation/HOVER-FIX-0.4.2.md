# 0.4.2 悬浮光标切换修复验证

日期：2026-09-19。Windows 11 x64，10.0.26100，12 个逻辑处理器；单屏 3840 × 2160，175% 缩放（168 DPI）。Rust/Cargo 1.93.1、MSVC 14.44、Windows SDK 10.0.26100.0；Release、ThinLTO、静态 CRT、PerMonitorV2。比较已发布的 0.4.1 与本地 0.4.2。

**问题与修复**

旧版仅替换当前标准光标角色。应用可在 Raw Input 之后，或在鼠标静止时因悬浮控件而改用手形、文本等角色；新角色尚未放大，需要等待后续输入或最长 100 ms 的停留检查。自建窗口在停留检查刚结束后切到手形，不再产生输入，最终回归在旧版测得 109.683 ms，早期复现为 108.227 ms。

新版在尺寸或朝向变化时，将同一缓存帧同步到 13 种受支持的标准光标。只切换角色时无需重绘或替换；缓存、识别算法、输入采样、停留频率及恢复机制保持原有约束。完整桌面回归测得手形切换 0.381 ms，最终专项复验为 0.556 ms。这是驱动调用切换到读到正确像素和热点的耗时，含查询开销，不是屏幕呈现延迟或物理鼠标端到端延迟。

每次几何变化由一次系统光标替换增加至最多 13 次，共用一帧栅格化结果。标准角色的系统副本有额外成本；帧缓存仍最多 16 帧、核算位图数据最多 2 MiB、闲置 3 秒清空。没有新增钩子、常驻线程、覆盖层或周期位置轮询。

**行为与恢复**

- 54 项 Rust 测试通过；格式和 Clippy 警告视为错误的检查通过。
- 旧版原有 86 项桌面检查通过；最终新增悬浮断言在旧版失败，证明原回归没有覆盖本问题。新版完整桌面回归 113 项通过，专项悬浮检查 26 项通过。
- 覆盖鼠标静止时切换、13 种角色的放大像素和热点、返回同一角色时不重复安装、自定义和隐藏光标、连续跨区域晃动、点击、滚轮、拖拽、边缘朝向、暂停和应用排除。
- 自动结束、暂停、进入排除应用、正常退出、主进程崩溃或挂起、恢复进程失效、整个进程树结束后的下次启动，均核对全部 13 种标准角色恢复。
- 16 轮触发及缓存清理后，主进程 GDI 15 → 15、USER 16 → 16、内核句柄 196 → 196；恢复进程 GDI 0 → 0、USER 1 → 1、内核句柄 110 → 110。缓存帧与核算字节归零。
- 8,192 条突发输入产生 128 次采样，耗时约 3.059 秒，程序保持启用。排除应用内持续输入 10 秒时，Raw Input、采样、动画检查及光标更新均为 0，离开后新手势正常触发。

桌面驱动使用独立配置和自建窗口，结束后恢复指针、前台窗口和原鼠标位置。验证覆盖与侧边栏悬浮控件相同的标准光标切换机制，未直接验收 Codex 侧边栏的特定控件或应用自带光标。
